01 / 鉴权与 Cookie 存档

注册时勾选「加入开发者计划【beta】」，或在游戏设置中进入开发者计划并加入。随后在 Key 管理页 创建 User Key。

推荐在每次请求中携带 X-User-Key: YOUR_USER_KEY，也兼容 Authorization: Bearer YOUR_USER_KEY。不要将 Key 放入 URL、请求体或 Cookie。两个鉴权请求头同时出现时必须一致。

接口不要求网页登录，也不要求 CSRF Token。Key 的创建、吊销和计划设置则需要网页登录及 CSRF 验证。有效 Key 可以直接调用下表接口。

Key 鉴权，Cookie 保存航程。

客户端必须保留响应的 Set-Cookie，并在后续请求中带回 Cookie。只带 Key、不保留 Cookie 的独立请求会开启新航程。Python 客户端请使用同一个 CookieJar，curl 请使用 -b 和 -c。另一程序无法仅凭 Key 读取浏览器内的存档。

有效 Key 对应的账号决定使用哪个存档；其他账号的 Cookie 不会被读取。多客户端共享同一份 Cookie 时，请将调用串行执行，避免互相覆盖。

所有成功请求（包括 GET 查询）都会先结算自动拖网，最多补结算 1 小时，并返回更新的 Cookie。规则失败不会提交游戏存档，待结算收益会在下次成功请求时处理。

当前服务地址：{{ base_url }}。纯 JS 站点（Sites / GitHub Pages）不提供这些 API。

钻石兑换与上限

1 兆 = 10¹² 金币，常规兑换按整兆结算，零钱保留；兑换档位越高，抽中概率越低。持币严格超过 10⁹ 兆时，任意兑换份额都将消耗全部金币，应发 INT64_MAX 钻石，钱包溢出部分销毁。

03 / 返回格式

成功返回 HTTP 200，JSON 包含 ok、data、完整的 state、storage 和 auto_catches。以下为 GET /getpays 示例：

{
  "ok": true,
  "data": {"gold": 12500.5, "diamonds": "42", "catches": 6},
  "state": {"gold": 12500.5, "diamonds": "42", "catches": 6, "level": 3, "...": "其余游戏状态"},
  "storage": "signed-cookie",
  "auto_catches": 0
}

gold 是 F64 数字，封顶于 1.7976931348623155e308；diamonds 始终为十进制字符串，最高 "9223372036854775807"，请使用 BigInt 或整数解析。

POST /upgrademain 无需请求体，每次升级一级，与网页「升级一次」使用相同费用和 Lv.870 上限。data.levels 为本次升级数（成功时为 1），最新等级及金币见 state.level、state.gold。金币不足或满级返回 400，不扣资源。

POST /fish 的 data.catch 含鱼类 ID、gold 收益、new 首次发现标记。兑换结果含 spent、rate、minted、awarded、destroyed、special；钻石数量均为字符串。special=true 时 rate=null。

GET /tujian 的 data 含 total、unlocked（已捕获、档案已解锁）和 locked（尚未捕获）。每条记录的 available 表示等级能否捕获，required_level 为所需等级，caught 为捕获次数。未捕获的鱼保留名称和稀有度，完整描述与体长在首次捕获后开放。

04 / 调用示例

curl：保持同一个 Cookie jar

export ABYSS_USER_KEY='替换为你创建的 User Key'

curl -sS -b abyss-cookies.txt -c abyss-cookies.txt \
  -H "X-User-Key: $ABYSS_USER_KEY" \
  -X POST '{{ base_url }}/fish'

curl -sS -b abyss-cookies.txt -c abyss-cookies.txt \
  -H "X-User-Key: $ABYSS_USER_KEY" \
  '{{ base_url }}/getpays'

curl -sS -b abyss-cookies.txt -c abyss-cookies.txt \
  -H "X-User-Key: $ABYSS_USER_KEY" \
  '{{ base_url }}/tujian'

Python：requests.Session

先安装客户端依赖：python -m pip install requests。

import os
import requests

with requests.Session() as client:
    client.headers.update({"X-User-Key": os.environ["ABYSS_USER_KEY"]})
    response = client.post("{{ base_url }}/fish", timeout=15)
    response.raise_for_status()
    print(response.json()["data"])

    response = client.get("{{ base_url }}/getpays", timeout=15)
    response.raise_for_status()
    print(response.json()["data"])

Session 会在同一进程内自动保留 Cookie；跨进程继续航程时需要额外保存并加载 Cookie jar。

Python：标准库 CookieJar，无需额外依赖

import json
import os
from http.cookiejar import CookieJar
from urllib.request import HTTPCookieProcessor, Request, build_opener

client = build_opener(HTTPCookieProcessor(CookieJar()))
client.addheaders = [("X-User-Key", os.environ["ABYSS_USER_KEY"])]

def call(path, method="GET"):
    req = Request("{{ base_url }}" + path, method=method)
    with client.open(req) as response:
        return json.load(response)

print(call("/fish", "POST")["data"])
print(call("/getpays")["data"])
print(call("/tujian")["data"])

重复捕鱼应等待至少 0.65 秒。标准库 CookieJar 只在当前脚本进程存活；需要跨脚本运行保存时，可改用 MozillaCookieJar 并在调用前后 load / save。

05 / 错误代码

HTTP含义
400没有渔网、未解锁兑换、金币或钻石不足、装备满级等规则不满足。
401Key 缺失、格式错误、无效或已吊销。
403账号未开启开发者计划；Key 管理操作的 CSRF 验证失败。
405HTTP 方法不正确，请按手册使用 GET 或 POST。
429手动捕鱼仍在冷却中，请稍候重试。
{"ok": false, "error": "先在船坞购买自动拖网"}

规则失败不会扣除金币或钻石。可在 Key 管理页 随时吊销 Key，后续调用立即失效。完整 Key 不会再次返回，服务端仅保存其哈希及可识别前缀。
